# Internationalization (i18n)

## Locales

Supported locales: `it` (default for system admin), `de`, `en`.

Each authenticated user stores a `locale` preference. Guests and the install wizard use the association default (`app.locale`, default `it`).

## File layout

```
lang/
  it/messages.php
  de/messages.php
  en/messages.php
```

Each file returns a flat or nested PHP array of keys. Access via helper:

```php
__('members.title');
__('members.status.active');
```

Missing keys fall back to Italian, then to the key string itself.

## Conventions

- Keys use `dot.notation` grouped by domain: `auth.*`, `members.*`, `payments.*`, `settings.*`, `plugins.*`, `install.*`, `nav.*`, `validation.*`.
- Do not hardcode UI strings in views; always use `__()` / `trans()`.
- Member type names and custom field labels may store JSON `{"it":"...","de":"...","en":"..."}` for user-defined content.

## Adding strings

1. Add the key to `lang/it/messages.php`.
2. Mirror it in `de` and `en`.
3. Never commit English-only UI for admin surfaces.
